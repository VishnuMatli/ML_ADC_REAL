# Load-Cell ADC R-DAE Pipeline and Realtime Visualization Report

Date: 2026-11-12
Project: Load-cell ADC noise reduction, feature extraction, FCM health-state grouping, and realtime process visualization

## 1. Executive summary

This project processes load-cell ADC recordings through a temporal recurrent denoising autoencoder (R-DAE), extracts latent features, groups the feature vectors with Fuzzy C-Means (FCM), and constructs a health/degradation indicator.

The latest work adds a realtime visualization program, `loadcell_realtime_visualization.py`. The program uses one ADC file and updates a six-panel dashboard while the pipeline is running. The dashboard makes the intermediate processing visible from raw input through final health-trend output.

The current pipeline successfully demonstrates:

- ADC file loading
- Moving-average pseudo-clean target generation
- Chronological train/validation/test splitting
- Temporal window construction
- LSTM R-DAE training
- Live training and validation loss updates
- Bottleneck feature extraction
- FCM clustering
- Test-window reconstruction
- Health/degradation trend calculation
- CSV and image output generation

The current implementation is a working engineering pipeline and visualization. It is not yet a validated physical degradation or RUL system because the data has no failure-time labels, all recordings use the same nominal 535 g load, and the ADC-to-grams calibration has not been implemented.

## 2. Important interpretation of the ADC data

The input files contain raw ADC counts, for example:

```text
ADC:44374172
```

This means the measured ADC value is approximately 44.37 million counts. It does not mean the value is 44.37 grams.

The filename contains the experimental load condition:

```text
535g20250502pm427ms20hz50.txt
```

The `535g` portion identifies the applied load used during the experiment. It is metadata, not an ADC-to-weight conversion.

The visualization therefore displays the signal as:

```text
ADC value (millions of counts)
```

A true weight axis in grams requires a calibration relationship learned from known pairs such as:

```text
ADC count -> physical load in grams
```

No such conversion is currently applied in the realtime visualization.

## 5. Detailed explanation of the base pipeline code

### 5.1 Imports and configuration

The base pipeline imports:

- NumPy for arrays and numerical calculations
- Matplotlib for plots
- TensorFlow and Keras for the LSTM model
- scikit-learn for scaling and evaluation metrics
- `Path` for file paths

The main configuration values are:

```python
WINDOW_SIZE = 32
EPOCHS = 25
BATCH_SIZE = 32
```

Meaning:

- `WINDOW_SIZE = 32`: every model sample contains 32 sequential ADC measurements.
- `EPOCHS = 25`: the complete training dataset is processed 25 times in the normal pipeline.
- `BATCH_SIZE = 32`: 32 windows are used in each optimizer update.

The realtime test command may use fewer epochs, such as one or two, to verify the visualization quickly. A normal run uses the default 25 epochs.

### 5.2 `load_adc_file`

Purpose: read one ADC text file and create the raw and pseudo-clean signals.

Processing steps:

1. Open the selected text file.
2. Read each line.
3. Keep lines containing `ADC:`.
4. Extract the numeric portion after `ADC:`.
5. Convert values to floating-point numbers.
6. Reject the file if it contains too few valid samples.
7. Create a sample-index time axis.
8. Create a 31-sample moving-average reference.

The central operation is:

```python
kernel = np.ones(smooth_window) / smooth_window
clean = np.convolve(noisy, kernel, mode='same')
```

The variable meanings are:

- `noisy`: original raw ADC values
- `clean`: smoothed pseudo-clean target
- `t`: sample index from zero to the number of samples minus one

The moving-average signal is called pseudo-clean because it is generated from the same raw recording. It is not an independently measured clean signal.

The use of `mode='same'` creates edge effects at the beginning and end of the smoothed reference because the convolution does not have a full window at those boundaries. These edge effects are visible in the first visualization panel.

### 5.3 `split_signal`

Purpose: divide the signal chronologically.

The default proportions are:

- 70% training
- 15% validation
- 15% test

The split is chronological rather than random. This preserves the order of the measurement and reserves the final section for testing.

The function returns:

```text
train_noisy, train_clean
val_noisy, val_clean
test_noisy, test_clean
```

The noisy and pseudo-clean arrays are split at the same sample boundaries so the model input and target remain aligned.

### 5.4 Normalization with `MinMaxScaler`

The raw ADC values are large, while the R-DAE output layer uses a sigmoid activation. Therefore, the values are transformed to the range `[0, 1]` before entering the model.

The scaler is fitted using both raw and pseudo-clean values:

```python
signal_scaler.fit(
    np.concatenate([noisy.reshape(-1, 1), clean.reshape(-1, 1)])
)
```

Each split is then transformed using the same scaler. This ensures that training, validation, and test values use a common numerical scale.

After model prediction, the reconstructed values are inverse-transformed back to ADC-count units for visualization.

### 5.5 `create_sequences`

Purpose: convert a one-dimensional signal into overlapping temporal windows.

For each valid start position, the function creates:

```text
data[i : i + WINDOW_SIZE]
```

With `WINDOW_SIZE = 32`, each model sample contains 32 consecutive points.

The resulting shape is:

```text
(number_of_windows, 32)
```

Before entering the LSTM, it is reshaped to:

```text
(number_of_windows, 32, 1)
```

The final dimension represents one ADC feature at each time step.

### 5.6 `build_rdae`

Purpose: build the temporal recurrent denoising autoencoder.

Architecture:

```text
Input: 32 time steps x 1 ADC feature
        |
        v
Encoder LSTM: 40 units, return sequences
        |
        v
Bottleneck LSTM: 24 units
        |
        v
RepeatVector: repeat bottleneck 32 times
        |
        v
Decoder LSTM: 24 units, return sequences
        |
        v
Decoder LSTM: 40 units, return sequences
        |
        v
TimeDistributed Dense: 1 output, sigmoid activation
```

The encoder compresses the noisy sequence into a latent representation. The decoder expands that representation back into a sequence intended to approximate the pseudo-clean target.

The model is compiled with:

```python
Adam(learning_rate=1e-3)
loss='mse'
metrics=['mae']
```

Meaning:

- Adam updates the model parameters.
- MSE measures the squared difference between predicted and target sequences.
- MAE is reported as an additional absolute-error measure.

### 5.7 Training data flow

The model receives:

```text
Input: normalized noisy windows
Target: normalized pseudo-clean windows
```

The training call uses validation data:

```python
model.fit(
    X_train,
    y_train,
    validation_data=(X_val, y_val),
    epochs=EPOCHS,
    batch_size=BATCH_SIZE,
)
```

The training loss shows how well the model fits the training windows. The validation loss shows how well it performs on the held-out validation section.

### 5.8 `extract_bottleneck_features`

Purpose: convert the trained model output into features for health-state grouping.

The function creates an encoder-only model using the trained bottleneck layer:

```python
encoder = Model(model.input, model.get_layer('bottleneck').output)
```

For every noisy test window, it obtains:

- `latent`: 24-dimensional bottleneck representation
- `pred`: R-DAE reconstruction
- `residual`: absolute reconstruction error

It then computes three error statistics per window:

```text
error_mean = mean absolute error in the window
error_std  = standard deviation of absolute error
error_max  = maximum absolute error in the window
```

The final feature vector is:

```text
[24 latent values, error_mean, error_std, error_max]
```

Therefore, the feature matrix has 27 columns in the current implementation.

### 5.9 `improved_fcm`

Purpose: group feature vectors into three fuzzy health-state clusters.

The function performs the following loop:

1. Select initial cluster centers.
2. Calculate squared distances from every feature vector to every center.
3. Calculate fuzzy membership values.
4. Update each center using membership-weighted feature values.
5. Repeat until membership changes are smaller than the tolerance or the maximum iteration count is reached.
6. Assign a hard label using the strongest membership.

Outputs:

- `centers`: cluster center feature vectors
- `membership`: fuzzy membership matrix
- `labels`: strongest-cluster label for each window
- `health_indicator`: `1 - maximum membership`

The cluster number itself has no inherent meaning. Cluster 0 is not automatically Healthy and Cluster 2 is not automatically Degraded. The health-trend stage later orders clusters by reconstruction error.

### 5.10 `reconstruct_signal`

Purpose: convert overlapping window predictions back into a continuous one-dimensional signal.

Each predicted window contributes to its corresponding positions in the full test signal. When multiple windows cover the same position, their predictions are averaged using a count array.

Conceptually:

```text
reconstructed value at position j
= sum of all window predictions covering j
  divided by number of windows covering j
```

This allows the window-based model output to be compared with the reference and noisy test sequence in the original sample domain.

## 7. Health-trend calculation

The `build_health_trend` function first extracts the mean reconstruction error for each test window.

For each cluster, it calculates the average error. The clusters are then sorted from lowest error to highest error:

```text
lowest error -> healthy-side
middle error -> warning-side
highest error -> degraded-side
```

The fuzzy cluster severity is calculated using the membership matrix and the severity ranks.

The reconstruction-error severity is min-max scaled:

```text
reconstruction_severity =
    (error - minimum_error) / (maximum_error - minimum_error)
```

The combined score is:

```text
raw_degradation =
    0.6 * fuzzy_cluster_severity
    + 0.4 * reconstruction_severity
```

The score is smoothed with a centered 31-window moving average.

The trend slope is calculated with a first-degree polynomial fit:

```text
slope = linear slope of smoothed degradation over window order
```

The monotonicity ratio is:

```text
number of non-negative consecutive changes
------------------------------------------
all consecutive changes
```

The state thresholds are currently:

```text
0.00 to below 0.33 -> Healthy
0.33 to below 0.66 -> Warning
0.66 to 1.00       -> Degraded
```

These thresholds are engineering thresholds only. They are not yet learned from failure labels or expert annotations.

5. Display the input and reference in the first dashboard panel.

7. Normalize values using one MinMaxScaler.

12. Update the training panel after every epoch.
13. Extract the 24-dimensional bottleneck features.
14. Calculate reconstruction-error statistics.
15. Create a 27-dimensional feature matrix.
16. Apply three-cluster FCM.
17. Display feature clusters and centroids.
18. Reconstruct the test sequence by averaging overlapping predictions.
19. Inverse-transform the test output back to ADC-count units.
20. Display reference, noisy, and reconstructed test signals.
21. Order clusters by reconstruction error.
22. Calculate fuzzy severity and reconstruction-error severity.
23. Smooth the combined health/degradation score.
24. Calculate trend slope and monotonicity.
25. Assign Healthy, Warning, and Degraded states.
26. Display the final health trend.
27. Save the dashboard image and per-window CSV.

## 11. Limitations

### 11.1 No ADC-to-grams calibration

The code displays raw ADC counts in millions. The `535 g` value comes from the filename and is not calculated from the ADC signal.

### 11.2 Pseudo-clean target

The moving-average reference is generated from the same raw signal. It is not an independently measured clean load-cell signal.

### 11.3 Fixed load

The available dataset uses the same nominal 535 g applied load. The model has not been proven to generalize to other weights.

### 11.4 No failure labels

There are no failure timestamps, degradation annotations, or remaining-useful-life labels. Therefore, an RUL accuracy claim cannot be made.

### 11.5 Operating-condition variation

The filenames include different frequency conditions. Changes in frequency or recording duration may affect the features and health trend independently of physical degradation.

### 11.6 Pseudo-clean edge effects

The moving-average convolution uses `mode='same'`, which can create artificial boundary behavior at the beginning and end of the reference signal.

### 11.7 Temporal split scope

The current experiment splits one file chronologically. A stricter generalization test should hold out complete files or complete operating conditions.

### 11.8 Cluster identifiers are arbitrary

FCM cluster numbers do not have fixed health meanings. The code correctly reorders them by mean reconstruction error before calculating severity.

### 11.9 Reconstruction quality

The reconstruction plot is useful for observing behavior, but the current model and pseudo-clean target require further calibration before reconstruction error is treated as a physical health measurement.

### 11.10 RUL is not implemented

The current pipeline ends at health/degradation trend generation. RUL prediction is not part of this visualization program and should not be inferred from the current state counts.

A concise explanation for a professor is:

> We developed a single-file load-cell ADC processing pipeline. The raw ADC text file is parsed and converted into a smoothed pseudo-clean reference for supervised denoising. The latest work makes the complete intermediate process visible in realtime for one ADC file. It demonstrates how the raw file becomes normalized temporal data, how the R-DAE learns, how latent features are produced, how FCM groups the windows, and how the health trend is calculated and saved.

