## 2. New processing flow

The current flow is:

```text
Raw ADC file
    -> ADC-to-weight conversion
    -> Chronological weight split
    -> Target generation from raw weight
    -> Weight normalization and windows
    -> LSTM R-DAE training
    -> Weight-domain reconstruction
    -> Weight residual/degradation explanation
    -> Final weight-domain summary
```

The current implementation has eight visualization stages.

## 3. ADC-to-weight conversion

The ADC file contains values such as:

```text
ADC:44374172
```

The code converts those raw values using a provisional ratio:

```text
weight = ADC_value / median(ADC_values) * 535 g
```

This produces weight values in grams for the rest of the workflow.

Important limitation:

- `535 g` is the nominal applied-load condition from the file metadata.
- It is not yet a calibrated ADC-to-grams conversion model.
- A proper calibration requires several known ADC and weight pairs.

## 4. Stage-by-stage changes

### Stage 1: ADC input and weight conversion

The first window now shows:

- Raw ADC input for reference
- Converted weight in grams
- Nominal 535 g condition line
- Explanation that the conversion is provisional

All later stages use the converted weight signal rather than raw ADC counts.

### Stage 2: chronological weight split

The converted weight signal is divided chronologically into:

- 70% training data
- 15% validation data
- 15% test data

The plot shows the three regions and reports the number of generated temporal windows.

### Stage 3: target generation from raw weight

The target is generated from the raw converted weight using a 31-sample moving average.

The window displays:

- Raw converted weight
- Generated target weight
- Raw weight minus target residual
- Residual variation
- Mean absolute residual
- Residual standard deviation

This makes the filtering procedure visible rather than hiding it inside preprocessing.

### Edge-artifact correction

The original smoothing used zero-padding behavior at the signal boundaries, which caused the generated target to drop artificially near the beginning and end of the plot.

The smoothing was corrected to use edge-value padding:

```python
padded = np.pad(raw_weight, (smooth_window // 2,), mode='edge')
target = np.convolve(padded, kernel, mode='valid')
```

The target now remains aligned with the raw weight signal at the boundaries.

### Stage 4: weight normalization and temporal windows

The weight signal and generated target are scaled to `[0, 1]` for neural-network training.

The window shows:

- One normalized input window
- One normalized target window
- A matrix of temporal windows entering the R-DAE
- Input shape and window size

The model still uses 32-sample temporal windows.

### Stage 5: R-DAE training

The LSTM recurrent denoising autoencoder receives:

```text
Input: normalized noisy weight window
Target: normalized generated target-weight window
```

The training window shows:

- Training MSE loss
- Validation MSE loss
- Loss values after each epoch

MSE is used only for model training and validation loss as requested.

### Stage 6: weight reconstruction

The model prediction is converted back from normalized values into grams.

The window shows:

- Raw converted weight
- Generated target weight
- R-DAE output weight
- Weight residual
- Raw-weight MAE against target
- R-DAE-output MAE against target

The reconstruction output is assembled from overlapping windows by averaging their contributions.

MSE is no longer used for the weight reconstruction comparison. The reconstruction comparison is expressed in grams using MAE and residual values.

### Stage 7: reason for degradation

The degradation explanation window now uses weight-domain evidence:

- Raw weight trend
- Generated target trend
- R-DAE output trend
- Raw-minus-target residual
- Smoothed residual variation
- Raw weight slope
- Target slope
- Residual slope
- Weight range
- Residual standard deviation

The explanation identifies whether apparent degradation is associated with:

- An increasing or decreasing raw-weight drift
- A changing residual trend
- High residual variation
- Weight range around the nominal load

This is an explanatory diagnostic, not yet a validated physical failure detector.

### Stage 8: final weight summary

The final window reports:

- Input file
- ADC sample count
- Mean converted weight
- Weight range
- Train, validation, and test window counts
- Final training MSE
- Final validation MSE
- Raw-weight MAE against target
- R-DAE-output MAE against target

It also states that the final output is a reconstructed weight signal and weight-domain degradation evidence.

## 9. Current interpretation

The current result proves that the complete software flow works in weight units after the initial ADC conversion.

The output should be interpreted as:

```text
ADC measurements
    -> provisional weight values
    -> smoothed weight target
    -> R-DAE weight reconstruction
    -> weight residual diagnostics
```

The positive or negative residual indicates the difference between the raw weight and generated target:

```text
positive residual: raw weight is above target
negative residual: raw weight is below target
```

The current degradation explanation is based on observed weight drift and residual variation. It should not yet be described as a confirmed physical degradation or RUL prediction.

## 10. Remaining limitations

- ADC-to-weight conversion is provisional and needs calibration data.
- The target is generated by smoothing the same raw weight signal.
- No independent clean weight reference is available.
- No failure-time or RUL labels are available.
- The current degradation explanation is diagnostic, not a validated failure classifier.
- The same nominal 535 g condition is used, so generalization to other loads is not established.
